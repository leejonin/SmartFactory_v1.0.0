공정 수를 1~4개로 선택하며 기본값은 1개다. 선택된 공정만 표시·운행·집계한다. 개수 변경은 진행을 초기화하고 AGV 대수는 유지한다. 화면 용어는 공정으로 통일했다.

AGV는 출발 지점 X=10에서 X=12.1까지 이동한 뒤 인계 소유권을 해제한다. 기존 X=16 해제보다 빠르며, 출발 경로에 X=12.1 경유점을 추가해 예약 구간도 분리했다. 선대기 중 또는 선대기로 이동 중인 AGV의 기존 구간 예약을 유지한 채 인계 지점을 경로 끝에 추가한다. 충돌 영역이 겹치면 실제 이동은 여전히 대기한다. 컨베이어 이동·합류·간격·QR 처리 코드는 변경하지 않았다.

검증: npm test 15개 통과, npm run build 성공, git diff --check 통과. 기존 번들 경고 821.15kB/gzip224.90kB 유지. Codex 내장 브라우저에서 공정 수 4→2→3→1 전환, 도크 12→6→9→3 표시 및 1공정 장면을 확인했다. AGV 최종 변경 후 장시간 브라우저 관찰은 미확인이다.

3대 AGV·30분·1/60초·동일 난수원으로 변경 전후 비교: seed 1 출하 97→98/QR 대기초 1364→1359, 27 출하 93→95/1372→1365, 998 출하 96→98/1364→1356, 4587 출하 99→99/1354→1351, 65535 출하 94→94/1371→1371. QR 대기초는 waiting 상자가 존재한 모의시간 합계다. 실제 QR 픽셀 판독 대신 목적지 반환으로 배차만 비교했고, 별도 전체 테스트에서는 실제 QR 검증을 수행했다. 개선은 제한적이며 병목 제거 완료가 아니다. 기존 단일 AGV 테스트의 30분 출하 합은 48→47, 2대는 80→80, 3대는 95→96으로 경유점 추가의 이산 시간 영향도 관찰됐다. 모든 구성에서 처리량 향상을 보장하지 않는다.

사용자가 현재 구현을 수락하고 추후 피드백하기로 했다. 앱 v0.0.12. 신규 day는 오늘 1개이고 신규 변경은 24시간 미만이므로 자동 문서 push 조건 미충족. 코드·문서 커밋 및 원격 배포는 수행하지 않았다. 기존 기록은 보존한다.
